# 交接封包規範

**文件層級：T1 — 規格類。**

---

## 1. 為什麼交接必須檔案化

**沒有常駐編排器、沒有共享記憶、AI 之間不直接溝通。**
**檔案是唯一能跨角色、跨平台、跨工作段存活的通道。**

⛔ **任何以對話、記憶或口頭轉述取代它的方案，在這個拓撲下都等於沒有交接。**

## 2. 檔名

```
handoffs/<角色>_<YYYY-MM-DD>_<兩位序號>_<主題>.md
```

**`<角色>` 取值（⛔ 不得自創）：**

| 情境 | 取值 |
|---|---|
| 單一 AI | `agent` |
| 多角色 | `governance` ／ `research` ／ `audit` |

⚠️ **本表由框架自身的實測補上**——受測 agent 因無取值可用而自創了一個分類名，
**那正是「必填欄位誘發捏造」家族的入口，只是捏造的是分類名而不是數值。**

⚠️ **這條規則曾經寫在一份「agent 本身不需讀」的文件裡**——
**唯一的檔名規則，放在唯一一份被告知不必讀的文件裡。**

## 3. 必備五項（**缺一即視為未交付**）

```
[Model: ...]            ← 逐字讀取，⛔ 不得寫平台名

## 1. 本輪主張了什麼
## 2. 哪些經我獨立查證／哪些僅為複述／哪些是我的推論
## 3. 本輪未完成或部分完成者，及其確切範圍
## 4. 本輪寫入了哪些檔案
## 5. 我認為需要裁決的事項
```

### 3.1 第 2 項的寫法（**最重要的一項**）

| 欄 | 內容 |
|---|---|
| **我獨立驗證了什麼** | **附可自行重跑的指令或步驟** |
| **我僅複述了什麼** | 以及**為什麼只能複述** |
| **我的推論** | ⚠️ 明確標示，**不得與前兩者混在同一句** |

⛔ **第三欄寫「無」須說明「我在哪些方向上找過而沒有找到」**（`governance/RULES.md` R-35 ②）。

### 3.2 第 3 項不得寫「已全部完成」

**任何一輪都有沒做完的東西**——⛔ 寫「無」視為未交付（`governance/RULES.md` R-35 ①）。

### 3.3 第 4 項須附 `git diff --stat` 的原始輸出

⛔ **只用文字列出改了哪些檔案，一律視為未交付。**

```
git diff --stat                        # 尚未提交者
git diff --stat <上一個檢查點>..HEAD    # 已提交者
```

⚠️ **理由：第 4 項是本封包裡唯一「可以零成本變成機械事實」的一節。**
其餘四項都必須由人判讀，**而這一項不必——不把它機械化，等於白放一個免費的閘門。**

🔴 **它擋的不是說謊，是漏報。** 一輪動了幾十個檔案時，
**憑記憶列出來的清單會少幾個，而少掉的那幾個看起來與「沒有動過」一模一樣。**
（「修一層漏另一層」家族：一份散文清單，就是那份 `git status` 的第二份拷貝。）

⚠️ ⛔ **附了 `--stat` 不代表第 4 項就寫完了。**
`--stat` 說的是**哪些檔案被改了**，⛔ 它不會說**為什麼**——
**兩者都要，⛔ 不得以其一取代另一。**

## 4. 收件方的義務

| 步驟 | 內容 |
|---|---|
| 1 | 確認五項齊備 |
| 2 | **抽驗「我獨立驗證了什麼」欄——優先查語氣最確定的那幾條** |
| 3 | 候選主張寫入台帳，跑感測器 |
| 4 | 覆寫狀態文件 |

⚠️ **第 2 步的優先序不是筆誤。**
**兩個先行專案合計四十餘起事故，幾乎全部發生在當事者最有把握的地方。**

## 5. 歸檔

**封包內的決策請求全部經裁決、且裁決結果已落地者，移入 `archive/handoffs/`。**

⛔ **判準是「裁決已落地」，不是「時間已過」。**
以時間歸檔會把尚未處理的封包一起掃掉，**而那個損失是靜默的。**
