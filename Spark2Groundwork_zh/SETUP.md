# 初始化指導說明書

**對象：不需要任何程式背景。** 全程約 40 分鐘，其中 30 分鐘是你在回答問題。

> ⚠️ **請按順序做，不要跳。** 第 3 步之前的每一步，都是為了讓第 3 步的檢查真的跑得起來。

---

## 步驟 0：確認你需要的是這個

**本框架適合：**

- 你有一個**還沒成形的研究構想**，想把它變成可執行的提案
- 你會用 AI 協助，但**你要為結果負責**
- 你願意接受「多花 20% 的時間換取錯誤留下痕跡」

**本框架不適合：**

- 你要的是快速產出（本框架會拖慢你，那是刻意的）
- 你的工作沒有需要查證的事實主張
- ⛔ **你希望 AI 自主推進而你只看最終結果**——**本框架的核心假設與此相反**

---

## 步驟 1：安裝三樣東西（約 10 分鐘）

| 軟體 | 為什麼需要 | 怎麼裝 |
|---|---|---|
| **Git** | 記錄「AI 改了什麼」，讓你能逐行檢視 | https://git-scm.com/download/win（Windows）／ macOS 內建或 `brew install git` |
| **Python 3.9+** | 執行感測器 | https://www.python.org/downloads/ ⚠️ **安裝時勾選「Add Python to PATH」** |
| **一個 AI 工作環境** | 見下表 | — |

### 1.1 AI 環境：本框架不綁定任何一家

| 環境 | 可用性 | 備註 |
|---|---|---|
| 有檔案存取的 AI（Claude Cowork／Claude Code／Cursor／Antigravity 等） | ✅ **建議** | 感測器可由 AI 自行執行 |
| 純聊天介面（ChatGPT／Claude 網頁／Gemini 網頁） | ✅ 可用 | 你需要自己複製貼上檔案，並自己跑感測器 |
| 本機模型 | ✅ 可用 | 同上 |

⚠️ **若你用純聊天介面，`profiles/PROFILE_chat_only.md` 有專門的簡化流程。**

### 1.2 確認安裝成功

打開終端機（Windows：開始選單搜尋 `cmd`），逐行輸入：

```
git --version
python --version
```

**兩行都要印出版本號。** 若 `python` 沒反應，試 `python3`。

---

## 步驟 2：選一個情境設定（約 5 分鐘）

**打開 `profiles/` 資料夾，選一份**：

| 你的情況 | 選這份 |
|---|---|
| 只有你和一個 AI | `PROFILE_solo.md` |
| 多個 AI 分工（研究／治理／審計） | `PROFILE_multi_agent.md` |
| 沒有檔案存取，只有聊天視窗 | `PROFILE_chat_only.md` |
| 會用 Deep Research、n8n 等外部工具 | 上面任選一份 ＋ `PROFILE_external_tools.md` |

**每份 profile 會告訴你：哪些文件要留、哪些可以刪、感測器跑哪幾支。**

⛔ **不要全部都留。** 一份沒有人維護的治理文件，比沒有那份文件更糟——
**它會讓你以為有人在看。**

---

## 步驟 3：把框架變成你的專案（約 20 分鐘，**這一步不能外包給 AI**）

### 3.1 複製資料夾

把整個 `研究治理框架_v1/` 複製到你要放專案的地方，改成你的專案名稱。

### 3.2 填空

**以下檔案含 `<<<填空:...>>>` 標記，全部要填：**

```
governance/AGENTS.md          ← 專案是什麼、你的學術底線、你的倫理紅線
ledgers/Conjecture_Ledger.md  ← 你的第一批猜想
```

⚠️ **`governance/AGENTS.md` 的三個問題必須你親筆，⛔ 不得由 AI 代答：**

> **① 如果這個問題得到答案，哪一個既有的說法會因此站不住？**
> （不得答「增進理解」「填補空白」。**須指名一個具體的受害者。**）
>
> **② 這件事是還沒有人回答，還是已經有人回答而我不知道？**
> （這是事實問題，可用文獻檢索回答，**不是形容詞**。）
>
> **③ 為什麼是我要做這一題？**

**為什麼不能給 AI 代答：** 這三題是用來防止**研究議程被 AI 悄悄接管**的。
若你答不出第三題，你正在做的可能是 AI 覺得好做的題目，而不是你想做的題目。

### 3.3 建立版本控制

**Windows：** 雙擊 `記錄快照.bat`
**macOS／Linux：** 在專案資料夾執行 `bash scripts/harness/human_checkpoint.sh`

看到 `New checkpoint created.` 就成功了。

---

## 步驟 4：第一次執行感測器（約 2 分鐘）

```
python scripts/harness/run_selftest.py
```

**應該看到「自測全數通過」。**

⚠️ **如果沒通過，先不要改感測器。**
自測失敗代表**感測器本身壞了或環境有問題**，不是你的文件有問題。
把完整輸出交給 AI，並明說「這是自測，不是專案檢查」。

接著：

```
python scripts/harness/run_all_sensors.py
```

**新專案第一次跑，會出現一批 WARN，那是正常的**——
你的台帳還是空的，感測器在提醒你欄位沒填。

### 4.1 三個退出碼的意思

| 碼 | 意思 | 你該做什麼 |
|---|---|---|
| **0** | PASS | 繼續 |
| **1** | FAIL | **有確定的缺陷。** 修好再繼續 |
| **2** | **INCOMPLETE** | **查不了。** ⛔ **這不等於通過** |

⚠️ **第 3 個最重要。** INCOMPLETE 的意思是「感測器沒能檢查」，
把它當成通過，是本框架防範的第一類錯誤。

---

## 步驟 5：把構想交給 AI（約 5 分鐘）

**打開 `INITIALIZE_PROMPT.md`，把整份內容連同你的構想貼給 AI。**

那份 prompt 會要求 AI：

1. 先讀治理文件，並**複述它的寫入範圍**
2. 把你的構想**拆成編號的猜想**，每一條附反證條件
3. **不要**直接開始查文獻——**先讓你確認拆解對不對**

⚠️ **第 3 點是刻意的。** 若拆解就錯了，後面查再多文獻都是在證明錯的東西。

---

## 步驟 6：之後每一輪怎麼跑

```
      ┌─────────────────────────────────────────┐
      │  ① 派工前：記錄快照.bat（建立檢查點）      │
      │  ② 跑 run_all_sensors.py 確認全綠         │
      │  ③ 把任務交給 AI                          │
      │  ④ AI 收工，交出交接封包                   │
      │  ⑤ 查看變更.bat（看它改了什麼）            │
      │  ⑥ 你裁決 → 更新台帳                      │
      │  ⑦ 再按一次 記錄快照.bat（＝我看過了）     │
      └─────────────────────────────────────────┘
```

⚠️ **第 ⑦ 步不是形式。** 它移動一個叫 `reviewed` 的標記，
**下一次的「改了什麼」是從這裡開始算的。** 不按，你就會重複看同樣的東西。

---

## 步驟 7：你會遇到的三件事，先講

### 7.1 感測器會誤報

**會。而且第一次誤報時你會想關掉它。**

⛔ **不要調鬆判準。** 正確處置是修比對邏輯，並**補一個「必須不誤報」的測試樣本**。
`governance/RULES.md` R-19 有完整說明。

### 7.2 AI 會在最有把握的地方出錯

**兩個先行專案合計四十餘起事故，幾乎全部發生在當事者語氣最確定的段落。**

→ 所以 `governance/Audit_Protocol.md` 要求：**抽查最確定的那幾條，不是最不確定的。**

### 7.3 你會想跳過台帳

**登錄一筆主張要填錨點和頁碼，比直接寫一句話慢五倍。**

⚠️ **而那正是它的作用：填頁碼會逼你真的去翻那一頁——
而翻到那一頁，你就會看見它跟你以為的不一樣。**

## 附：常見問題

**Q：我可以只用一部分嗎？**
可以，`profiles/` 就是為此而設。**但主張台帳與 Git 檢查點建議保留**——那兩者的成本最低、回報最高。

**Q：AI 可以自己更新台帳嗎？**
⛔ **不建議。** 台帳是「你確認過什麼」的紀錄。AI 直接寫入，就沒有人在確認了。
正確做法：AI 以**決策請求**格式回報 → 你裁決 → 寫入。

**Q：我不會用 Git，一定要嗎？**
**兩支 `.bat` 就是為了讓你不必會。** 你只需要記得兩件事：
**派工前按一次、看完後按一次。**

**Q：這套東西會不會太重？**
會，如果你全部都用。**這正是 `profiles/` 存在的理由。**
⚠️ 而且請注意：**本框架自己也有一條規則叫「文件增生防線」**——
它假設治理文件會膨脹，而不是假設你會克制。
