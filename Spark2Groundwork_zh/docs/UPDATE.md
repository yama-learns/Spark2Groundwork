# 更新、儲存與已閱：不用貼命令

## 先分清按鈕

Windows 雙擊 .bat，Mac 雙擊同名 .command。只閱讀結果，最後按鍵關閉；缺工具先看 [啟動說明](START_HERE.html)。

| 按鈕 | 功能與寫入 |
|---|---|
| 儲存進度 | 用既有 Git 快照保存目前內容；可初始化 Git，寫提交與快照紀錄，但不移動「已閱」標記 |
| 記錄快照 | 沿用原本的人工已閱確認。只有你看完內容才按，會更新已閱標記；AI不得代按 |
| 查看變更 | 讀取已閱標記到目前內容的差異；不表示你已讀完，不改標記 |
| 檢查更新 | 線上查版本；若已有 _upgrade，再做本機逐包差異。只查不套用 |
| 同步規則 | 先保存工具還原點，失敗則不補規則；補缺少的條文，不覆寫既有條文／自訂規則，再檢查文字漂移 |

只想先存檔或內容尚未讀完，一律按「儲存進度」。新專案尚無人工已閱基準時，先讀自己的初始內容再按「記錄快照」，才開始派工；缺少基準時查看變更會清楚提示，不能把暫用 HEAD 當成人工已閱。

## 不寫程式的更新流程

1. 暫停各 AI 寫入、關閉正在編輯的文件。把**整個專案（包含隱藏的 .git 與設定）**複製到專案外的備份資料夾，確認研究檔可開。備份不要放在專案內；有未讀工作只按「儲存進度」，不要按人工已閱。
2. 從原 GitHub 庫下載新 ZIP，解壓縮。只取与你專案相同語言的完整資料夾。將它放到專案根目錄的 `_upgrade/` 中；保留完整的 Spark2Groundwork_zh 或 Spark2Groundwork_en 資料夾，不混語言。
3. 按「檢查更新」。讀版本與差異；只看得到版本號並不證明下載完整。網路不通時本機差異仍可做；查不到最新版不能稱已是最新。
4. **一次只換一包**：governance、profiles、prompts、scripts、docs。先請 AI 或自己比較清單，把舊包內任何自建研究檔／工具移到專案自有位置（例如 my/tools）並修正引用；不確定歸屬就先停。把舊包移到專案外備份處，再將新版同名完整資料夾放進來；不要直接合併覆蓋而留下已退役舊檔。每包更換後讀差異；有問題先停，其餘包不要繼續。
5. 根目錄只替換 README.md、SETUP.md、INITIALIZE_PROMPT.md、file_index.md 與本語的框架按鈕。舊版根指引若有自訂文字，先移到專案自有文件並保留連結。自己的 PROJECT.md、第一個想法.md／FIRST_IDEA.md、my、ledgers、corpus、corpus_md、governance_config.json 與任意自建檔案都保留原位。不要把整個專案換成新下載資料夾。
6. `.gitignore` 與 `.gitattributes` 有混合所有權，不能整份覆寫。請 AI 比較新舊預設，只補缺少的必要規則，保留使用者自訂。單語專案可只留本機的 .bat 或 .command；Mac 新按鈕若被擋，按啟動說明處理該檔案，不能整批解除安全檢查。
7. 換完 governance 後，按「同步規則」。出現 RULE_TEXT_DRIFT 時，請 AI列出條文差異，由你確認要採新版或保留有理由的專案覆寫；只編輯那一條，不替換整份 my/MY_RULES.md。再按同步規則確認；文字漂移未解不算完成。
8. 所有預定包換完，按「檢查專案」及「查看變更」。中途版本不一致會被報告，不能把部分更新當完成。你確實審閱後，才按「記錄快照」建立新的已閱基準。保留備份直到驗收完成。

這條手動路徑不提供逐包自動交易或還原點，**專案外完整備份**才是復原來源。若途中失敗，停下並保留訊息；在另一個位置還原完整備份再確認，不覆蓋唯一殘存的研究資料。具有本機執行能力的 AI 可在你授權後使用既有逐包升級程式；它的工具還原點也不代表你已閱。沒有本機執行能力的 AI 仍可協助讀清單，你不用代貼命令。

## 舊專案要另外看三件事

- v1.4.2以前放在prompts/TEMPLATE_decompose.txt的構想，先保存到根目錄第一個想法.md（英文FIRST_IDEA.md）；自建工具移至my/tools，保留引用。多AI專案若授權治理角色维护my，請AI在你的governance_config.json只補該角色必要write_scopes，不覆蓋設定。
- v1.4.4已退役policy/，新版改放governance/。先確認SOURCES.md、MODEL_IDENTITY.md、HANDOFF.md、EXTERNAL_TOOLS.md都在新版governance，再把舊policy移到專案外保存。手動替換不會自動找出或移走這個舊資料夾。
- v1.4.1／1.4.2更新可能曾不當移動「已閱」標記。若不確定目前基準可信，不用該標記保證未讀工作已被列出，也不猜測回退位置。先保存完整備份，請AI協助盤點並完整重讀需負責的研究內容，確認後你再按人工已閱按鈕。需要精確歷史調查時，由具本機執行能力的AI處理；不要讓使用者貼Git命令。

## Mac Finder檔與連線錯誤

新預設忽略.DS_Store，但舊專案已被Git追蹤的Finder檔不會自動退出追蹤。請有本機執行能力的AI**先列出Git確實追蹤的.DS_Store完整相對路徑**，你確認後只取消這些檔的追蹤、保留磁碟原件；不得廣泛清除或刪研究檔。AI無執行能力時先保留，這類中繼檔可稍後處理；不聲稱已清理。

TLS／憑證錯誤：確認日期時間、網路登入頁及官方Python安裝說明中的憑證設定；不要停用驗證、下載陌生憑證或交出帳號密碼。DNS／斷網：稍後重試，或另從官方頁下載ZIP後做本機差異。不論原因，查詢失敗不等於最新版本不存在。無限等待／異常工具請關閉結果視窗並保留訊息；不要連按、清鎖或重裝覆蓋研究檔。
