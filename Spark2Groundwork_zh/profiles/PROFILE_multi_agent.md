# 情境設定：多 AI 角色分工

**適用：** 兩個以上的 AI 各司其職，且**至少兩家不同的模型**。

---

## 1. 三個角色

| 角色 | 職掌 | 建議模型 |
|---|---|---|
| **治理** | 事故紀錄、流程維護、治理文件、感測器 | 主力模型 |
| **研究** | 內容迭代：文獻判讀、分析、假設檢驗 | 主力模型 |
| **審計** | 對抗審計。**不做產出、不修缺陷** | ⚠️ **必須是不同家的模型** |

⛔ **審計者與被審者為同一模型時，這一層等於沒有。**
**兩家模型的盲點不同，這是配對的全部理由。**

## 2. 三個接觸面，**全部經過人**

| 接觸面 | 規則 |
|---|---|
| **台帳** | ⛔ 任何 AI 都不得寫入。以決策請求回報 → 你裁決 → 治理角色執行 |
| **狀態文件** | 每條線一份，**互不寫入、互不複製內容** |
| **`handoffs/`** | 三者皆可寫。⚠️ **檔名須帶角色前綴，否則會互蓋** |

## 3. `framework_config.py` 設定

```python
"write_scopes": {
    "governance": ["governance", "policy", "scripts", "file_index.md", "NEXT_SESSION_MEMO.md"],
    "research":   ["research", "corpus_md", "RESEARCH_MEMO.md"],
    "audit":      ["scratch"],          # 沙盒；報告寫 handoffs/
    "_shared":    ["handoffs"],
}
```

⚠️ **給審計角色一塊沙盒是必要的。**
先行專案曾要求對抗審計卻沒給審計者實驗地，**等於要求它要嘛不測、要嘛越界。**

## 4. 多角色架構的**特有風險**

### 4.1 換手時就要存檔，不是收工才存

⚠️ **兩條線在同兩個檢查點之間工作，變更就無法歸屬**——
你會看到一堆變更，而分不清哪些是誰做的。

### 4.2 治理角色也要交封包

⚠️ 先行專案的治理角色長期只寫自己的備忘而不交封包，
**結果是其他角色只會在下次違規時才發現規則變了。**

⛔ **凡本輪變更影響到他人的權限、規格或工具行為，一律須交封包並指名收件人。**

### 4.3 誰來審計治理角色

**這是最容易被漏掉的一個環節，因為提出它的人通常就是治理角色本身。**

**觸發條件（不是每輪都審）：** 感測器程式碼變更、T0 變更、寫入範圍變更、新增事故。

**治理層的四個攻擊點，有別於研究層：**

| # | 問法 |
|---|---|
| G-1 | **同一規則有幾個版本？** 兩處是否一致？ |
| G-1b | **新規則會不會與某條既有規則在「同時遵守」時互相排斥？** 特別問**規則層 vs 工具層** |
| G-2 | 這個修正動到哪一層，又**迫使哪一層跟著改**？ |
| G-3 | **新檢查的成對樣本，兩半都在嗎？** |
| G-4 | 這個排除／例外的**代價寫下來了嗎**？ |

⚠️ **G-1b 的來源：** 某專案在同一輪寫下「會變的數字不寫進條文」並據以移除文件中的數目，
而既有感測器的條件是「沒有文件載明數目 → FAIL」。**遵守新守則的當下，舊感測器立刻判 FAIL。**
**兩條規則都是同一個人寫的，而衝突只有在同時遵守它們時才會現形。**
