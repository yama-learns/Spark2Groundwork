# 情境設定：多個 AI 分工

**適用：** 你使用兩個以上的 AI 分工。可選不同模型或供應商以補充觀點，不是必要資格；獨立覆核須由未參與該部分生成或修復的工作者承接。角色權限與交接見第 1、2 節。

---

## 1. 角色分工

研究、治理、審計的預設權限統一見 `governance/WORKFLOW_CONSTITUTION.md` §6。角色不是型號或供應商指定；獨立覆核由未參與該段生成的人員承接，多元模型可補充觀點，不保證沒有盲點。

## 2. 共用與交接

台帳工作紀錄可由AI維護，人類裁決須有真實來源。各角色可寫自己的工作目錄與共用備忘／交接；同檔並行先分工，不覆蓋未合併成果。審計可建立報告與測試，受託修復後列作者。

## 3. 每一輪怎麼跑

```
你按「記錄快照」
   → 派工給研究角色                    → 它交出封包
   → 派工給治理角色（若本輪有規則要動）  → 它交出封包
   → 你按「查看變更」，看兩邊各改了什麼
   → 你裁決 → 治理角色把裁決結果寫進台帳
   → 你再按一次「記錄快照」
```

### 3.1 換手就存檔，⛔ 不是收工才存

⚠️ **兩條線在同兩個檢查點之間工作，變更就沒辦法歸屬。**
你會看到一大堆改動，⛔ **而分不出哪些是誰做的。**

**每換一個角色，按一次「記錄快照」。** 這是這個情境裡最便宜也最有效的一個動作。

### 3.2 治理角色也要交封包

⚠️ **這一點很容易被漏掉，因為治理角色寫的是「規則」，感覺不像「產出」。**

**但規則變了而別人不知道，後果是：其他角色會在下一次違規時才發現規則變了。**

⛔ **凡是這一輪的變更會影響到別人的權限、格式或工具行為，一律要交封包，並指名收件人。**

---

## 4. 誰來審計治理角色

🔴 **這是整個架構最容易漏掉的一環——因為會想到這個問題的人，通常就是治理角色本人。**

**不必每輪都審。有這四種情況才審：**
檢查程式被改了、行為準則被改了、寫入範圍被改了、新增了一筆事故。

**審計治理角色時，問的問題和審研究角色不一樣：**

| # | 要問的 |
|---|---|
| **G-1** | **同一條規則現在有幾個版本？** 不同檔案裡寫的一致嗎？ |
| **G-2** | **這條新規則，會不會和某條舊規則「同時遵守時互相排斥」？** |
| **G-3** | 這次修改動到哪一層，**又逼得哪一層非跟著改不可**？ |
| **G-4** | **新增的檢查，「該報警」與「不該報警」兩種樣本都有嗎？** |
| **G-5** | 這次開的例外，**代價寫下來了嗎**？ |

⚠️ **G-2 值得多說一句，因為它最難自己發現。**

**一個真實的例子：** 某輪同時發生兩件事——
規則層新增了「會變動的數字不要寫進條文」，於是文件裡的數目被拿掉了；
而工具層有一支既有的檢查，判準是「文件裡沒有寫出數目 → 判定失敗」。
🔴 **遵守新規則的當下，舊檢查立刻判失敗。**
**兩條規則都是同一個角色寫的，⛔ 而衝突只有在同時遵守它們的那一刻才會現形。**

---

## 5. 框架怎麼在這個情境下持續變好

🔴 **多角色的優勢，就在這一節。**

**單人情境要靠你自己記得把事故寫下來；多角色情境可以把它變成一個角色的職責。**

### 5.1 事故由治理角色維護，⛔ 由你結案

🔴 **三個角色各有一份開工指令，開新對話時整份貼過去：**

| 角色 | 貼這一份 |
|---|---|
| 治理 | `prompts/START_治理AI.md` |
| 研究 | `prompts/START_研究AI.md` |
| 審計 | `prompts/START_審計AI.md` |

**「登記事故」這件事已經寫在治理角色那一份裡了**——
**⛔ 你不需要自己再交代一次。**

⚠️ **「狀態」欄改成「已處置」仍然只有你能決定。**
**理由與台帳相同：如果角色可以自己宣告事情處理完了，那一欄就不再代表任何事。**

### 5.2 審計角色的第二個用途：找模式

**大約每十輪，把 `my/MY_INCIDENTS.md` 整份交給審計角色，問：**

> 「這些事故裡，哪幾筆其實是同一個機制的不同外觀？
> 對每一個機制，告訴我：現有規則為什麼沒擋住它？」

🔴 **這件事交給審計角色，比交給治理角色好。**
**因為那些沒擋住事故的規則，就是治理角色自己寫的**——
**要一個人挑出自己規則的漏洞，比讓另一個人來挑困難得多。**

### 5.3 新規則由你裁決，⛔ 不由提議者自己通過

**流程固定成這樣：**

```
審計角色提出 → 治理角色評估可行性與代價 → 你裁決 → 治理角色寫進 my/MY_RULES.md
```

⛔ **不要讓提議的人自己核准。**
**這不是不信任，是因為提議的人已經被自己的想法說服了**——
**他評估不了那個想法的代價，因為在他眼中那個代價是值得的。**

### 5.4 這樣做的結果

**你會得到一份愈來愈貼近你這個題目的規則集，
而且它的每一條都經過「有人提議、有人評估、有人裁決」三道。**

⚠️ **這比單人情境慢，⛔ 但也比單人情境紮實**——
**單人情境的規則只有一個人看過。**

---

## 6. 設定

新專案預設 `deny: []`、`write_scopes: {}`，不需手動分配目錄。角色能力依憲章 §6；審計可自行建立沙盒與持久報告。現行感測器只查範圍聯集，不驗角色身分。舊專案升級保留自訂值；AI可依使用者選擇協助最小調整，不靜默取消限制。個人設定寫在 `governance_config.json`，不直接改會隨升級替換的框架預設。測試證據移出暫存區後再引用。
