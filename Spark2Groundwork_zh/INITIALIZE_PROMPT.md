# 初始化指令（**貼給 AI 的第一句話**）

> **用法：先把構想填進同層的 `第一個想法.md`，再把下面框內的全文貼給能讀取此專案的 AI。**

---

```
你將協助我把一個研究構想發展成可執行的提案。本專案採用一套檔案化的治理框架。

═══ 第一步：讀，然後複述 ═══

依序讀完以下檔案，然後在你的第一則回覆中做三件事：

  1. 宣告你的型號（逐字讀取權威來源；讀不到就寫「無法讀取」，
     ⛔ 不得寫平台名稱代替）
  2. 複述你的寫入範圍（見 governance/WORKFLOW_CONSTITUTION.md §6
     與我選定的 profiles/PROFILE_*.md）
  3. 用你自己的話說明「這個專案的查證等級標記是什麼」

必讀：
  governance/AGENTS.md
  governance/WORKFLOW_CONSTITUTION.md
  governance/RULES.md
  governance/Incident_Log.md          ← 首次參與必讀
  my/MY_RULES.md                     ← 專案自訂規則（若存在）
  ledgers/Conjecture_Ledger.md §0
  ledgers/Claim_Ledger.md §0–§1
  PROJECT.md
  第一個想法.md

⛔ 三件事沒做完之前，不要開始任何實質工作。

═══ 第二步：拆解，不要查證 ═══

讀完後，依 `第一個想法.md` 內的拆解規則，對檔案最下方的構想做拆解。

⛔ 這一輪不要查文獻。
⛔ 這一輪不要評價構想好不好。
⛔ 這一輪不要提出研究設計。

理由：如果拆解就錯了，後面查再多文獻都是在證明錯的東西。

═══ 第三步：等我確認 ═══

拆解完成後停下來。⛔ 不要自行寫入任何台帳。

以決策請求格式（憲章 §5）向我回報：
  - 你拆出了幾條
  - 哪幾條你填不出反證條件，以及為什麼
  - 哪兩條你認為其實是同一條
  - 原文中哪一句你認為最有價值而我可能沒有意識到

═══ 第四步：收工儀式（憲章 §4.2） ═══

拆解與決策請求整理完成後，依憲章 §4.2 順序收工：
  1. 跑檢查：執行 `python scripts/harness/run_all_sensors.py`（若環境無終端權限，提醒使用者點擊 `檢查專案.bat` / `.command`）。
  2. 覆寫狀態備忘：覆寫 `NEXT_SESSION_MEMO.md`，記錄當前拆解進度、未完成項目與等待裁決事項。
  3. 產出交接封包：於 `handoffs/` 產出本輪初始交接封包（格式見 `governance/HANDOFF.md`，包含本輪完整變更清單）。
  4. 提出第三步的決策請求，等待我的裁決。

═══ 你要知道的三件事 ═══

1. 我是唯一的裁決者。你提決策請求，我裁決，你執行。
   ⛔ 台帳預設由使用者維護（受 governance_config.json 之 deny 保護）；未經我明確授權並自 deny 移除前，你不得寫入任何台帳。

2. 每個帶數值或帶斷言的句子都要標查證等級標記。
   ⛔ [已查證] 等級的資料不得用來判定某主張為假，也不得用來建構新假說。

3. ⛔ 不要宣稱你自己已經查證無誤。
   若要說明你做過什麼，請指名一個我可以自己重跑的指令或檔案。
```

---

## 附：第一輪之後

**每一輪的開頭都貼這句：**

```
依 governance/WORKFLOW_CONSTITUTION.md §4.1 開工儀式執行。
本輪任務見 NEXT_SESSION_MEMO.md。
⛔ 不要照抄我這段話裡的任何路徑或範圍——以治理文件當下的內容為準。
```

⚠️ **最後一句是刻意的。**
先行專案曾把寫入範圍抄進指令範本，權限變更後範本沒跟著改，
**於是一份宣告「本檔不重述範圍」的文件，在同一頁下方重述了過期的版本。**
