# CI-0：v1.4.5 最小回歸檢查（r6）

## 目的與信任邊界

CI 自動重跑已定義的回歸條件，檢出少跑、缺件、錯誤參數、失敗傳遞、超時及環境不完整。綠燈表示這個版本在列明環境通過這些檢查；不表示研究正確、人類已審閱、可發布或所有平台皆可用。

CI-0 **不提供對同權限惡意 runner／launcher／checker 的執行真實性證明**。這些程序可讀取測試檔、改寫收據甚至更改檢查器。隨機值用於防止誤用舊輸出及增加抽樣覆蓋，不是保密或身分認證。刻意辨識測試並偽造輸出的風險，由獨立程式覆核、精確候選綁定及合併授權共同處理；不能只靠綠燈接受測試基礎設施本身的變更。

以下變更在合併前必須由未參與生成的覆核者檢查 diff：`.github/workflows/**`、`scripts/check_repo_hygiene.py`、`tests/**`、兩語 `scripts/harness/run_selftest.py`、`run_all_sensors.py`、`selftest/**`、所有 `.bat`／`.command`，以及本規格。涉及感測器與核心也依既有覆核程序。這是流程要求；本卡沒有啟用遠端 branch protection、CODEOWNERS 或可信隔離執行服務，不宣稱已有平台強制措施。

## 工作流

| 觸發 | 執行矩陣 |
|---|---|
| PR（main、work/**） | Linux / Python 3.9；Windows / Python 3.12 |
| push（main、work/**）或手動 dispatch | Linux、Windows、Apple Silicon macOS、Intel macOS，各 Python 3.9 / 3.12，共 8 組 |

每個 job 上限 15 分鐘；矩陣 fail-fast 關閉，以保留其他平台結果。僅 `contents: read`，checkout 不保留認證，沒有 secrets、PR target、部署或自動發布。外部 action 固定完整 commit SHA；測試依賴固定 pytest 8.4.2、PyYAML 6.0.3（未宣稱所有遞迴相依皆已 lock）。

遠端 runner 名稱不代表已實測。工作流首次上線須在批准的精確提交執行，保存 run URL、SHA、各組結果；Python 或 runner 不可用是未完成，不是通過。下載包行尾與 `.command` 可執行權限仍須在整合／封裝時驗證；本地檔案複本及 bash 代跑不證明 Git index mode、ZIP 權限或 Finder／Gatekeeper。

## 三類檢查

1. **檔案與入口前置**：雙語結構、24 個預期啟動檔、`.bat` CRLF、shell/Python LF、shebang、封閉參數、明顯提前退出、bash 語法、Python 3.9 語法、無 bytecode／執行產物。靜態行掃描是快速 lint，不能證明所有控制流程可達。
2. **一次性專案回歸**：每語在包外 Git 專案跑原 selftest，核對精確 186 個預期名稱、無重複／缺件／失敗；另跑 aggregate sensors，核對新生成 status 的十支集合，再由 checker 逐支執行並比較退出碼。任何 exit 1／2、錯誤或 timeout 均不能綠燈。case 名稱清單是可維護契約，不是不可變神聖數字；真正新增／修改測例時，附 diff 同步更新並覆核，不為湊數保留無意義測例。
3. **失敗傳遞與原生啟動**：正常基線成功後，各語抽取六個已有負向感測器家族之一，於新副本注入回傳 0 或 3 的受控錯誤。必須有指定 fixture 的載入紀錄、指定原先通過 case 轉為預期失敗、runner exit 1、該 case 不再通過；不以一般 `failed` 字樣或任意非零退出充數。選擇、變異前後 hash、輸出皆記錄。這是抽樣故障回歸，不宣稱覆蓋所有十支或防惡意偽造。每個平台的六個原生入口各測 stub exit 0／1／2（納入 1 是因為把 FAIL 吞成 PASS 是傷害最大的誠實回歸），核對新收據的本次識別、精確 lang/action 及退出碼傳遞。stub 記錄實際 Python 路徑／版本；原生啟動器自行選出的 Python 不一定等於 matrix Python，不能混報。

## 執行、證據與失敗處理

維護者在可丟棄的 repo 副本執行：

```text
python -B scripts/check_repo_hygiene.py --all
python -B -m pytest -p no:cacheprovider tests/test_ci_workflow.py
```

凍結工作包先複製到包外，不直接在候選內執行。checker 在 job log 留下實際版本、命令、stdout/stderr、退出碼、抽樣與啟動收據；timeout 的部分輸出也保存。工作包驗證另由包外 `verify.py` 處理，不在發布的 pytest 中放一個永遠 skip 的工作包測試。

缺 bash 時 exit 2；其他檢查失敗 exit 1，均不視為成功。禁止 `continue-on-error`、自動重跑直到綠燈或將已知產品故障改 skip。失敗保留原始輸出；修復後的新執行另存，並列候選差異。若是新能力或同權限攻擊研究，另列後续工作，不以新增字串探針無限延長本卡。

## CI0-O1：必要的基準修復

既有 checkpoint 在同大小、相同／低精度檔案時間資訊下，普通 Git add 可能沿用快取而漏掉內容替換。r6 在正常 add（處理新增／刪除與 ignore）後只對一般 tracked 檔（H 標記）追加 renormalize，保留 assume-unchanged／skip-worktree 的既有排除語意；失敗即 exit 2。`git add --pathspec-from-file` 需 Git 2.25 以上；當 Git 拒絕的是這個選項本身時，改以分批 literal pathspec 參數重試，讓舊版 Git（例如 Apple Git 2.24）仍可建立檢查點；真正的 staging 失敗仍回傳 2，不會默默略過檔案。這會重新套用既有 Git clean／行尾規則並增加已追蹤檔案讀取成本；不改 reviewed 的工具模式語意，也不取消 upgrade 的 durable receipt 安全閘。CI 新增可重現反例與新增／刪除／忽略／no-op／失敗不提交的測試。此產品修補須隨本候選獨立覆核，不能套用 X89 的舊接受。

官方參考（2026-09-22查閱）：[Git add](https://git-scm.com/docs/git-add)、[GitHub runner 規格](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)。

舊 Git 退路只在 C locale 下 exit 129 且明示 unknown/unrecognized pathspec-from-file 選項時啟用；usage 字樣不是充分條件。分批以 16,000 預算同時計入引號後 UTF-16 長度、UTF-8 參數 bytes 及執行檔餘裕；程序啟動或路徑檔失敗均 exit 2、不建立新 commit。單語產品各自附 CHECKPOINT-STAT 決定性的同大小／同時間內容回歸，新增一個真測例（167 → 168）。每次完整驗證測 12 個本平台原生入口 × 0/1/2 = 36 次。舊 Git 選項回應以注入模擬，真舊 Git 與遠端 runner 需另行實測。
